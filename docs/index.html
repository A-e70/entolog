entolog

Turn a folder of photographs into a species record table, with the fields you decide on, from the window, the terminal, or the image viewer you already use.

Download one file Source on GitHub Viewer integration

Standard library Python 3.9 or newer. No packages. Nothing is uploaded and nothing leaves your machine.

The photograph already knows when and where

You know what. entolog reads the date and the position out of the EXIF, works out a grid reference, and takes the rest as fast as you can type it.

filename      date        time      latitude   longitude  locality                   species       stage  sex     comments
IMG_0421.jpg  2026-06-14  09:26:07  51.753792  -1.257281  Wytham Woods, Oxfordshire  Vespa crabro  adult  female  on ivy, sunny bank

Three ways in, one record

The same profile, the same validation, the same storage, the same exports. Use whichever suits the hour.

A window

Photograph, form, keyboard shortcuts. Bursts are grouped so one record covers the whole event.

python3 -m entolog ~/photos/june

The terminal

One line per specimen. Abbreviations resolve, Tab completes, nothing is guessed when it is ambiguous.

> Vespa crabro / adult / f / on ivy
saved 3 photographs

Your own viewer

feh, nsxiv, geeqie, anything that can run a command. entolog follows what you are looking at.

entolog current %f
entolog record - "vecr / adult"

The fields are yours

A profile is a JSON file listing what a record contains. The storage, the form, the terminal grammar, the shortcuts, the autocomplete, the validation and the export columns are all generated from it. Adding a field is editing a file, not editing entolog.

{
  "name": "moths",
  "primary": "taxon",
  "fields": [
    {"name": "taxon", "type": "text", "learn": true, "dwc": "scientificName"},
    {"name": "count", "type": "number", "min": 1, "dwc": "individualCount"},
    {"name": "trap", "type": "choice", "digits": true, "open": false,
     "choices": ["actinic", "MV", "LED", "sugar", "net"]},
    {"name": "host_plant", "type": "text", "learn": true, "key": "h",
     "dwc": "associatedTaxa"}
  ]
}

Ships with profiles for insects, general biodiversity and plants. Every field carrying a Darwin Core term travels into the GBIF, iRecord and NBN Atlas export on its own.

It is careful with a record

  • No GPS in the file. The position stays empty rather than guessed, and a filter lists exactly which photographs need a grid reference by hand.
  • No EXIF date. Falls back to the file's own timestamp, marks that it did so in its own column, and shows it in amber.
  • A value that fails a check is still stored. Losing what someone typed is worse than storing something odd.
  • Renamed or moved photographs keep their record, matched by fingerprint on the next scan.
  • Southern and western hemispheres come out negative rather than mirrored, which is the classic way a record lands in the wrong ocean.
  • Switching profile never deletes a value, and refuses to orphan a field that holds records unless you insist.

Getting it

curl -LO https://github.com/A-e70/entolog/releases/latest/download/entolog.pyz
python3 entolog.pyz ~/photos/june

# or from source
git clone https://github.com/A-e70/entolog && cd entolog
python3 -m entolog ~/photos/june
